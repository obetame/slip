# 2026-10-23

## 0.4.0：密条（secret slip）

用户提的需求是「有时会往板子上贴 token 或密码，产品该怎么处理」，讨论后决定：
不做密码管理器、不做静态加密全家桶，只加一种活得很短的纸条。用户又补了一条
「给密条单独一个口令，存密文」，采纳，但作为可选项而不是默认。

设计要点（写进了 docs/design.md 的「Secret slips」一节）：

- 正文从不进 `/api/items`，只能 `POST /api/items/{id}/reveal` 取，因为这一步会改状态
  （记读取、焚毁），所以用 POST 而不是 GET，好继续走 `X-Slip` 和 Origin 检查。
- `ttl` 1 分钟到 7 天，默认 24 小时；到期由原有 janitor 直接硬删，**不进 60 秒撤销窗口**。
  「撤销条」的意思是字节还在，而这正是密条不该承诺的。
- 阅后即焚按 `X-Slip-Device`（localStorage 随机值，服务端 sha256 取前 8 字节）判断
  「是不是写它的那台浏览器」。缺这个头就当成别人，宁可保守。
- 取件码：Argon2id(64MiB,t=2,p=2) → AES-256-GCM，盐/nonce/密文进 items.json，码不存。
  客户端生成 8 位（去掉 0O1IL 的 31 字母表），约 40 bit。连错 10 次自毁。
- 焚毁后留 1 小时墓碑（只有 takenAt），发送方能看到「已被取走」。
- 删除/清空对密条是硬删，`SoftDelete` 只把可恢复的 id 返回给撤销条。

明确拒绝并写进「不做」：自动识别"这像密钥"（假阴性更害人）、客户端加密
（`crypto.subtle` 只在安全上下文，局域网 HTTP 不是）、保险箱/零知识存储、HTTPS。

## 密条这一轮的体验修正（用户截图反馈）

1. **开关标签和说明没对齐**：根因是 `.hint` 自带 `margin: 8px 0 0` 且 14px，放进
   `align-items:center` 的 flex 行里就被顶下去。加 `.checkline .hint { margin:0 0 0 8px;
   font-size:13px }` 覆盖，两个页面各自一份。
2. **取件码要遮住**：输入框与「放下后那张卡片」默认都是 `type=password` / 圆点，
   各有「显示」切换（就地切 type，不重绘，光标不丢）；复制始终可用。
3. **提示不像提示**：`.secretnote` 改成便签样式（左侧 2px 印色竖线 + 暖底 + 12.5px），
   深色底 `#2b2320`。
4. **打开密条会跳回顶部**：根因是 `renderBoard` 里 `clear(node.main)` 会把页面清空，
   浏览器把滚动位置归零。改成 renderBoard 记 `pageYOffset` → `paintBoard()` → 滚回去，
   再由 `settlePrompt()` 把 `.codeprompt` 居中并 `focus({preventScroll:true})`。
   顺带解决了所有重绘（折叠、预览、删除）都会跳顶的老问题。
5. 顺手修的：操作顺序改成揭示后「复制」在第一（窄屏只留第一个）；墓碑不再给「打开」；
   焚毁后清掉本地 `sealed/burn`，否则头部还写着「密文」；头部显示「密文」；圆点
   `aria-hidden`；倒计时 30 秒自己更新（只改 `.meta` 的文本，不重绘，避免抢光标）；
   开着密条添加文件/拖放会说明「密条只收文字」而不是静默按普通纸条上传。

验证：`just test`、`scripts/browser-test.sh` 全绿；另写临时 jsdom 脚本（已删，用
`resources:"usable"` 真正加载样式表才能测到 computed style）确认 28 项全过。
jsdom 脚本要显式 `process.exit()`，否则 rAF 让进程不退出、被外层 kill 掉、输出丢失。

## 密条 UI 的第二轮（像素君视角，用户说"还是有点粗糙"）

先按要求把前一轮整体提交：`cacc601 Add secret slips that hide, expire, and burn...`。
设计改动单独一个提交：`eb3a512 Give the secret options one type scale and one field group`。

诊断：那个块里同时存在三套尺寸（13 说明 / 13 标签 / 16 按钮 / 44 控件），没有任何一档是"次要"，
所以怎么看都像拼的。修的是层级，不是单个像素：

- **字号三档**：13 标签（500）、12 说明（muted）、16 输入框（iOS 聚焦不缩放的下限）。
  说明比标签小一档，才读得成注释。
- **一个输入组**：取件码 + 显示 + 生成 装进同一个 38px 边框，内部用 1px 分隔线切成段，
  右下角主操作用印章色填充（卡片里的"打开"就是这么做的）。原来是一个 44px 输入框
  挨着一个 44px 按钮，各自带边框。
- **分组**：开关下面 24px 缩进（对齐到复选框右边），"阅后即焚"和"保留"并成一行 ——
  它们回答的是同一个问题。
- **面板感**：正文和选项之间加一条 1px 细线，选项从此是"这张纸条的设置"而不是正文的延续。
- **颜色**：`accent-color: var(--seal)` 让复选框从系统蓝变成印章色。这页唯一的冷色没了。
  （accent-color 在 css_compat 的禁用表里，但那只扫 tokens.css / legacy.css，app.css 安全。）
- **密码点**：16px 字号 + 字距从 0.14em 收到 0.08em（2.24px → 1.28px），另外去掉了
  `min-height: 44px` 的全局下限（`input[type=text]` 有 44px floor，必须显式 `min-height: 0`，
  否则组高度压不下来）。
- 顺手：`select` 改成 16px（低于 16 iOS 会缩放整页），12px 作为字号下限（11.5 中文发糊）。

验证：jsdom + `resources:"usable"` 加载真实样式表量 computed style，22 项（字号、38px、
字距 1.28px、缩进 24px、分组 display、遮罩、焦点、错误码），全过；`just test` 与
browser-test 全绿。注意 jsdom 不解析 shorthand 里的 var()，border-top 这类要直接读 CSS 文本断言。

## 第三轮：字号层级（commit 98a225a）

用户截图指出两处，其实是同一个病：**次要文字用了主文字的尺寸**。

- `::placeholder` 之前没有任何规则，直接继承输入框的 16px，于是成了整块里最大的字。
  改成 14px（muted、opacity:1）。输入框本身保持 16px —— 那是 iOS 聚焦不缩放的下限。
- 卡片里的说明继承 `.hint` 的 14px，而卡片头部的 meta 只有 13px，等于注释比标题还大。
  `.masked .hint / .secretbody .hint / .secretgone / .codecard .hint` 一律 12px，
  并把 `.masked .hint` 的 margin 归零（圆点行已经带了下边距）。

现在的字阶：16 输入值 / 14 占位符 / 13 标签与 meta / 12 说明。

注意：CSS 是通过 go:embed 打进二进制的，改样式必须重启 `just dev-local`；
`Cache-Control: no-cache` 只保证刷新会重新取，不保证进程里是新文件。

## 第四轮：两个原生控件的问题（commit 01aebb3, 891176a）

用户又指出「24 小时」很大、六个圆点很大。两件事根因都不在字号，在**控件本身**：

- `<select>` 要避免 iOS 聚焦缩放，就得 16px，于是它必然是那行里最大的字。三选一的
  东西本来也不该用下拉（把两个选项藏起来）。换成三颗 13px 芯片，28px 高，
  点选只切 className 不重绘（保住 textarea 光标）。印章色留给「放下」，芯片选中用墨色
  + `var(--bg)` 底，避免整块四处见红。
- 六个实心圆点是「密码框」的隐喻，而这里是**被遮住的正文**。改成三条涂黑线
  （5px 高、68/46/30% 宽、`var(--line)` 底色、`aria-hidden`），读作"有字，被涂掉了"。
- 顺手：「选填」原本被 `space-between` 推到最右边，和「取件码」隔了整行，改回紧跟标签。

验证：jsdom 量到芯片 13px/28px、点选只换 class 不重绘、选 1 小时后服务端 expiresAt 正好 1 小时、
涂黑条 3 条 5px、圆点已消失；`just test` 与 browser-test 全绿。

留给用户决定的：便签条（"同一 Wi-Fi 上能抓到明文"）仍是整块填充面板，是 composer 里除
「放下」之外最重的一件东西；两个复选框都是实心印章红，也偏重。这两个没动，因为都改过一次了。
