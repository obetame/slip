# 2026-10-23

## 0.4.0：密条（secret slip）

用户提的需求是「有时会往板子上贴 token 或密码，产品该怎么处理」，讨论后决定：
不做密码管理器、不做静态加密全家桶，只加一种活得很短的纸条。用户又补了一条
「给密条单独一个口令，存密文」，采纳，但作为可选项而不是默认。

设计要点（写进了 docs/design.md 的「Secret slips」一节）：

- 正文从不进 `/api/items`，只能 `POST /api/items/{id}/reveal` 取，因为这一步会改状态
  （记读取、焚毁），所以用 POST 而不是 GET，好继续走 `X-Slip` 和 Origin 检查。
- `ttl` 1 分钟到 7 天，默认 24 小时；到期由原有 janitor 直接硬删，**不进 60 秒撤销窗口**。
  「撤销条」的意思是字节还在，而这正是密条不该承诺的。
- 阅后即焚按 `X-Slip-Device`（localStorage 随机值，服务端 sha256 取前 8 字节）判断
  「是不是写它的那台浏览器」。缺这个头就当成别人，宁可保守。
- 取件码：Argon2id(64MiB,t=2,p=2) → AES-256-GCM，盐/nonce/密文进 items.json，码不存。
  客户端生成 8 位（去掉 0O1IL 的 31 字母表），约 40 bit。连错 10 次自毁。
- 焚毁后留 1 小时墓碑（只有 takenAt），发送方能看到「已被取走」。
- 删除/清空对密条是硬删，`SoftDelete` 只把可恢复的 id 返回给撤销条。

明确拒绝并写进「不做」：自动识别"这像密钥"（假阴性更害人）、客户端加密
（`crypto.subtle` 只在安全上下文，局域网 HTTP 不是）、保险箱/零知识存储、HTTPS。

## 密条这一轮的体验修正（用户截图反馈）

1. **开关标签和说明没对齐**：根因是 `.hint` 自带 `margin: 8px 0 0` 且 14px，放进
   `align-items:center` 的 flex 行里就被顶下去。加 `.checkline .hint { margin:0 0 0 8px;
   font-size:13px }` 覆盖，两个页面各自一份。
2. **取件码要遮住**：输入框与「放下后那张卡片」默认都是 `type=password` / 圆点，
   各有「显示」切换（就地切 type，不重绘，光标不丢）；复制始终可用。
3. **提示不像提示**：`.secretnote` 改成便签样式（左侧 2px 印色竖线 + 暖底 + 12.5px），
   深色底 `#2b2320`。
4. **打开密条会跳回顶部**：根因是 `renderBoard` 里 `clear(node.main)` 会把页面清空，
   浏览器把滚动位置归零。改成 renderBoard 记 `pageYOffset` → `paintBoard()` → 滚回去，
   再由 `settlePrompt()` 把 `.codeprompt` 居中并 `focus({preventScroll:true})`。
   顺带解决了所有重绘（折叠、预览、删除）都会跳顶的老问题。
5. 顺手修的：操作顺序改成揭示后「复制」在第一（窄屏只留第一个）；墓碑不再给「打开」；
   焚毁后清掉本地 `sealed/burn`，否则头部还写着「密文」；头部显示「密文」；圆点
   `aria-hidden`；倒计时 30 秒自己更新（只改 `.meta` 的文本，不重绘，避免抢光标）；
   开着密条添加文件/拖放会说明「密条只收文字」而不是静默按普通纸条上传。

验证：`just test`、`scripts/browser-test.sh` 全绿；另写临时 jsdom 脚本（已删，用
`resources:"usable"` 真正加载样式表才能测到 computed style）确认 28 项全过。
jsdom 脚本要显式 `process.exit()`，否则 rAF 让进程不退出、被外层 kill 掉、输出丢失。
